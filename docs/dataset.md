# Datasets: provenance and data dictionary

TransactionGuard uses two datasets and never mixes their results.

| | `creditcard` (benchmark) | `synthetic` (demo) |
|---|---|---|
| Kind | **Real** card transactions, **anonymized** with PCA | **Synthetic**, generated by this repo |
| Source | [OpenML dataset 1597](https://www.openml.org/d/1597), originally ULB Machine Learning Group / Worldline ([Kaggle page](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud)) | `src/transactionguard/data/synthetic.py` (seed 42) |
| Access | Public download from OpenML, no login | Generated locally |
| Licence | Original release: Open Database License, contents under the Database Contents License (DbCL) v1.0. OpenML lists "Public". | Same as this repository |
| Redistributed here? | **No.** Downloaded by `tg data prepare creditcard` | Generated on demand, also not committed |
| Rows / positives | 284,807 / 492 (0.173%) | 143,497 / 802 (0.559%) with the default config |
| Time span | ~48 hours (`Time` 0 → 172,792 s) | 60 days (2026-05-02 → 2026-06-30, UTC) |
| Used for | Benchmark claims | Installation checks, UI demo, history-feature showcase |

Citation for the benchmark: Andrea Dal Pozzolo, Olivier Caelen, Reid A. Johnson and Gianluca
Bontempi. *Calibrating Probability with Undersampling for Unbalanced Classification.* IEEE CIDM,
2015.

## Acquisition and integrity

`tg data prepare creditcard` reads the dataset description from the OpenML API, downloads the
original ARFF file, and **verifies its MD5 checksum** (`178bcf9bb1f31a3dfe12d0e577884add`) before
use. A mismatch deletes the file and stops. We parse the ARFF ourselves because OpenML marks
`Time` as the row-id attribute of dataset 1597, and `sklearn.datasets.fetch_openml` silently drops
it. A chronological split needs `Time`.

Every processed table gets an order-sensitive SHA-256 **fingerprint**. It is logged to MLflow and
stored in each model bundle, so a model can be traced to the exact data it was trained on.

- creditcard fingerprint: `b8777e83fa1386473b310f640b7618a07c2cde44927c4c98b6adb2e6223082c6`

## Data dictionary: `creditcard`

| Column | Type | Role | Meaning (as published, nothing invented) |
|---|---|---|---|
| `transaction_id` | string | id | Added by TransactionGuard from the original row order (`cc-000000`…). The source has no id. |
| `Time` | float (s) | timestamp | Seconds since the first transaction in the dataset. The real start clock time is not published. |
| `Amount` | float | feature | Transaction amount. The currency is not stated. |
| `V1` … `V28` | float | feature | Principal components released by the data owner. The original features and their meaning are confidential, so explanations can only name them. |
| `Class` | int | target | 1 = labelled fraud, 0 = genuine (source labels). |

Derived feature: `hour_of_cycle = (Time mod 86400) / 3600`. This is a position in a 24-hour cycle
measured from the first transaction. **It is not the local clock hour**, because the start time is
unknown.

Limitations: two days of data; one bank; 2013; no account or merchant identifiers (so no history
features or group split); anonymized features cannot be checked against business logic; and the
data contains duplicate rows with identical values.

## Data dictionary: `synthetic`

| Column | Type | Allowed values / range | Meaning |
|---|---|---|---|
| `transaction_id` | string | unique | Identifier |
| `timestamp` | datetime (UTC) | not in the future | Transaction time |
| `account_id` | string | | Paying account (used for history features and group splits) |
| `merchant_id` | string | | Merchant (used only for "first time at this merchant"; never one-hot encoded) |
| `amount` | float | 0.01 – 50,000 | Amount |
| `channel` | category | online, pos, atm, transfer | Channel |
| `merchant_category` | category | grocery, restaurants, fuel, fashion, electronics, travel, entertainment, utilities, gaming, crypto_exchange | Category |
| `country` | category | IN, US, GB, DE, SG, AE, NG, BR | Country |
| `is_fraud` | int | 0/1 | 1 if the row came from an injected fraud scenario |

How it is generated: each account has a home country, a spending level, preferred categories and
favourite merchants. About 10% of accounts experience one fraud scenario: an account-takeover
burst, card testing (many small online payments), or a single skimmed-card purchase. Legitimate
look-alikes are added on purpose (genuine travel abroad, occasional large purchases). **The
patterns were designed by the generator, so models find them easily.** Synthetic results are
labelled as such everywhere and are never used as evidence.

## The shared data contract

`src/transactionguard/data/contract.py` defines each dataset's columns once. From that single
definition we generate:

- batch validation (`data/validation.py`), which checks required columns, types, missing values,
  non-finite numbers, duplicate ids, valid categories, amount/time ranges and future timestamps;
- the strict API request model (`extra="forbid"`, no NaN/inf, categories as `Literal`);
- the dashboard's scoring form (`GET /api/v1/contracts/{name}`).

Missing required fields are **rejected**, never filled with defaults. The only missing values
the model sees are genuinely absent history (for example, an account's first transaction has no
"seconds since previous transaction"). Those get a learned median plus an explicit missing-indicator
column.
